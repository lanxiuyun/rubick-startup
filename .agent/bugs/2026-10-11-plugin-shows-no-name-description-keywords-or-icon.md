# 2026-10-11 插件列表里没有名称、描述、关键词，也没有图标

## 症状

Rubick 插件市场里插件显示成临时占位信息：没有名称、没有描述、没有关键词、没有图标。搜索 `fav` / `启动` 也搜不到。

## 根因一：清单放在子目录里，Rubick 只读根目录

最初把插件清单写成 `public/package.json`，而开发安装时 Rubick 读的是**项目根目录**的 `package.json`。于是它拿到的是一份空清单。

同时项目根目录确实有一份（内容还和子目录那份不一致，`cmds` 和 `explain` 都不同）—— 两份清单并存本身就是隐患。

**修复**：只保留根目录一份 `package.json`，删掉 `public/package.json`。并在 lint 里加一条断言，防止它复活：

```js
if (html.includes('id="query"')) fail(...)   // 同类思路：已删的东西不该回来
```

## 根因二：`logo` 不支持本地文件

官方文档明确写：`logo` **必须是 http/https 在线地址，不支持本地 logo**（尺寸建议 200×200）。

当时用的是本地 `public/logo.svg` —— 于是图标不显示。

**修复**：改成 `data:image/svg+xml;base64,...`（977 字符，塞进 `package.json` 的 `logo` 字段）。`data:` URI 属于在线地址范畴，实测可用。同时页面内的 `<img>` 也用同一个 data URI —— 插件页面其实是 `node_modules` 下的镜像目录，本地相对路径容易踩坑。

## 一个伴随的误判

页面空白过几次，一度被当成"页面坏了"。真实原因有两层：

1. **改了本地链接里的文件后 Rubick 不自动刷新** —— 在「开发者」页点"刷新插件"再重新安装就好了
2. **改了系统插件（bridge）必须完全重启 Rubick**，而改页面文件不用（页面每次打开重新读）

所以"UI 没更新"这个症状要分三种可能查：文件没被刷新 / 需要重启的是系统插件 / 真的代码错了。别一上来就怀疑代码。
