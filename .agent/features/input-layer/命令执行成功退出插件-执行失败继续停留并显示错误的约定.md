# 命令执行成功退出插件，执行失败继续停留并显示错误

`StartupApp.launch()` 捕获命令并清空搜索框后调用 `spawnCommand`。只有 Promise 成功才保存或更新历史并调用 Rubick `outPlugin()` 退出插件；失败不改历史、不调用退出接口，使用持续显示的错误消息展示原因。退出插件不等于退出 Rubick 程序，也不调用隐藏主窗口接口。

执行失败时，若该命令已有成功历史记录，则保留原 `time` 并添加保留标签 `error`；首次失败且没有历史记录时不创建记录。之后成功运行会移除该记录的 `error` 标签，并在所有错误记录恢复后移除空的 `error` 筛选标签。用户的其它标签不变。

## 成功的判断

- 文件夹：独立启动 `explorer.exe <path>` 并等待进程 `spawn`；不能把 `shell.openPath` 的空错误字符串当作 Explorer 窗口已打开的证据。
- 命令：等待 `cmd.exe` 的 `close` 事件且退出码为 0，不能把 `spawn` 当成执行成功。
- 非零退出码：优先显示 stderr，没有输出时显示退出码或终止信号。
- 命令未退出：继续等待，不用固定时间猜测成功或失败。前台长进程可能要等结束才退出插件。

`cmd /u` 的内置错误使用 UTF-16LE；外部程序还可能输出 UTF-8 或 Windows 本地编码。stderr 最多保留 64 KiB，解码后交给 React 文本消息显示，不解析为 HTML。命令子进程在 close 后再 unref，防止测试进程在异步断言结束前退出。

## 测试

`npm test` 中的 `runtime.test.js` 在 Windows 上执行真实 cmd，覆盖成功、未知命令、stderr、无输出的失败和中文错误；`visual.e2e.js` 验证成功退出、失败停留且失败命令不进入历史、长命令等待和文件夹错误。

## 文件日志与打开目录诊断

日志写入 `os.tmpdir()` 下的 `rubick-startup.log`，只保留在本机，不提交真实命令或目录。session 含诊断版本，environment 含进程与 Electron 版本信息。每次执行的 execution JSON 用 id 关联 request、stat/stat-error、explorer-request/explorer-spawn/explorer-error 或 cmd-request/cmd-spawn/cmd-close、result；plugin-exit 记录退出请求，plugin-stay 记录失败停留。文件写入失败会在控制台警告。

映射盘出现“插件退出但目录未显示”时，先核对插件进程的 stat 结果及 Explorer 的 spawn/error。终端能访问映射盘不等于 Explorer 的登录会话能访问；spawn 只证明进程创建成功，不保证最终窗口可见。
