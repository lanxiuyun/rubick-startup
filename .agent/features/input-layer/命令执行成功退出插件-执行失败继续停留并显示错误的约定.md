# 命令执行成功退出插件，执行失败继续停留并显示错误

`StartupApp.launch()` 捕获命令并清空搜索框后调用 `spawnCommand`。Promise 成功后保存历史，先调用 `hideMainWindow()` 隐藏 Rubick 主窗口，再调用 `outPlugin()` 退出插件；失败不隐藏、不退出，使用持续显示的错误消息展示原因。`outPlugin()` 单独调用只退出插件页面，不保证主窗口隐藏。所有命令和目录共用成功分支，没有 notepad 特例。

启动失败时，若该命令已有历史记录，则更新 `time` 为本次尝试时间并添加保留标签 `error`；首次失败且没有历史记录时不创建记录。之后成功启动会移除该记录的 `error` 标签，并在所有错误记录恢复后移除空的 `error` 筛选标签。用户的其它标签不变。

## 成功的判断

- 文件夹：独立启动 `explorer.exe <path>` 并等待进程 `spawn`；不能把 `shell.openPath` 的空错误字符串当作 Explorer 窗口已打开的证据。
- 文件夹路径在存在性检查前由 `normalizePath()` 统一 `/`、`\` 和重复分隔符；UNC 保留开头的 `\\`，其它重复分隔符合并。Explorer 收到归一化后的 Windows 路径。
- 所有命令（含参数）：提取首个入口，程序名用 `where.exe` 查询 PATH，带路径入口检查文件存在性，CMD 内置命令通过名单识别。查询设有超时，找不到入口不创建终端。
- 入口可用时通过可见的独立 `cmd /k` 控制台启动；收到 spawn 就保存历史并退出插件，不等待工具退出、不收集工具 stderr。参数错误和业务失败由终端显示，不算插件启动失败。
- 双引号包围的程序路径支持空格，原始命令参数不改写。复合命令只验证首个入口，后续部分由 CMD 处理；不是完整的 CMD 语法校验器。

进程独立运行并在 spawn 后 unref，插件退出不会等待工具结束。启动器只承诺入口预检查及进程创建成功，不承诺工具完成业务任务。

## 测试

`npm test` 中的 `runtime.test.js` 在 Windows 上真实查询 PATH、检查程序路径，模拟终端启动避免弹窗；浏览器测试覆盖带参数入口和内置命令、不等待长进程、找不到入口不入历史，以及失败重试更新时间和 error 标签。

## 文件日志与打开目录诊断

日志写入 `os.tmpdir()` 下的 `rubick-startup.log`，只保留在本机，不提交真实命令或目录。session 含诊断版本，environment 含进程与 Electron 版本信息。每次执行的 execution JSON 用 id 关联 request、stat/stat-error、explorer-request/explorer-spawn/explorer-error 或 cmd-request/cmd-spawn/cmd-close、result；plugin-exit 记录退出请求，plugin-stay 记录失败停留。文件写入失败会在控制台警告。

映射盘出现“插件退出但目录未显示”时，先核对插件进程的 stat 结果及 Explorer 的 spawn/error。终端能访问映射盘不等于 Explorer 的登录会话能访问；spawn 只证明进程创建成功，不保证最终窗口可见。
