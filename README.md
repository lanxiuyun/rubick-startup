# 启动收藏

**简体中文** | [English](README.en.md)

Rubick 插件「启动收藏」把路径和命令变成可搜索、可分类、可重复启动的历史列表。它复用 Rubick 搜索框：输入后回车，不必在插件里再输一次。

![启动收藏运行界面](docs/images/rubick-startup.png)

- Rubick 搜索关键词：`运行`、`启动`、`start`、`fav`
- 当前插件版本：`26.10.13`
- 开发验证环境：Rubick 4.3.8

## 安装

在项目目录运行：

```powershell
npm run deps
npm test
npm run install:rubick
```

安装后，在 Rubick 中搜索 `fav` 打开「启动收藏」。修改页面或代码后重建并重新打开插件；修改插件注册信息后需要重新安装。

```powershell
npm run check:rubick       # 检查安装链接和 Rubick 注册表
npm run uninstall:rubick   # 卸载插件
```

## 使用

Rubick 搜索框是唯一的命令输入框。记录列表显示最近运行的路径和命令，使用标签组织常用项目。

| 操作 | 行为 |
| --- | --- |
| 输入文本 | 第一行显示并选中当前输入；下方显示模糊匹配的历史记录 |
| 回车 | 执行当前选中行；当前输入行默认选中，因此直接回车执行输入原文 |
| `↓` / `↑` | 在当前输入行与匹配历史间移动选择 |
| 点击历史记录 | 直接启动该记录 |
| 点击顶部标签 | 按标签筛选记录；搜索与标签筛选可叠加 |
| 顶部 `+` | 新建空标签 |
| 右键记录 | 打开标签管理面板；可复制或删除记录 |
| 右键顶部标签 | 重命名或删除标签 |
| `Esc` | 清空搜索框 |

输入行只是临时操作项，不会预先写入历史，也没有标签或右键菜单。只有启动器确认入口存在并成功创建启动进程后，输入才成为历史记录。执行后搜索框会清空，防止重复运行。

## 启动与错误

- 文件夹路径支持正斜杠、反斜杠、重复分隔符及 UNC 格式；启动前会归一化为 Windows 路径并交给 Explorer。
- 命令通过可见的独立 CMD 窗口启动，工具退出码不用于判断启动器是否成功。Python、IPython 等交互程序可以持续运行；像 `dsh` 缺少参数这样的工具自身提示不阻止历史记录。
- 裸命令通过 `where.exe` 检查 PATH；带路径的可执行文件检查文件存在性；CMD 内置命令通过内置命令表识别。复合命令只检查第一个入口，其余语法由 CMD 处理。
- 找不到入口或启动进程创建失败时，插件保持打开并显示错误，不创建新记录。
- 已有历史记录再次启动失败时，会更新时间并添加红色 `error` 标签；之后成功启动会移除 `error`。时间表示最近一次尝试。
- 成功启动后先隐藏 Rubick 主窗口，再退出插件页面。

启动成功表示入口可用且进程已创建，不代表程序后续操作或业务任务成功。所有命令以当前 Windows 用户权限运行，只运行可信输入。

## 历史与标签

- 普通无标签记录最多保留 500 条，超出后淘汰最久未使用的记录。
- 有标签的记录不受 500 条上限影响，直到手动删除。
- 用户标签与自动 `error` 标签共存在同一条记录上；移除 `error` 不影响其他标签。
- 列表按最近尝试时间倒序排列；一条记录可以属于多个标签。

## 开发与检查

```powershell
npm run serve   # 启动本地开发服务器
npm run build   # 构建离线单 HTML 插件入口
npm test        # 构建并运行静态、模型、Windows runtime 和浏览器测试
```

构建产物位于 `public/index.html`，由构建生成，不要直接编辑。列表使用固定 `ROW_H = 56` 的虚拟滚动；改变行高时必须同步调整布局和常量。

发布前运行隐私检查：

```powershell
node tools/privacy-scan.js .
node tools/history-scan.js
```

详细模块索引见 [`.agent/manifest.yaml`](.agent/manifest.yaml)。
